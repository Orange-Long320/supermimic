# 原生 IMU 启动管道故障（2026-11-04）

## 现场故障与复现

用户 trial `run-keyboard-20261104-163038` 在校准前退出，状态包 0、校准 false、读取 103 条，全部过期且没有完整因果编码器。IMU header 最大间隔 2.027 ms、最大包龄 328.895 ms。`state/imu-reader.log` 的具体原因是 `Raw sensor pipe write failed`。

现有 C++ 读取器使用非阻塞 stdout 管道。管道实际容量 65536 字节，832 字节帧最多容纳约 78 帧。启动 DDS 积压突发与 Python 调度延迟可能填满管道；r7 只在已初始化后允许 EAGAIN，校准前会直接报错。是否触发取决于启动时序，不能因第一次能启动推断第二次必定可以。没有证据将本次故障归因于机器人移动或 IMU 原始采样中断。

在真实只读传感器上，对同一读取接口暂停 Python 消费 0.4 秒：r7 原样复现 `Raw sensor pipe write failed`，退出码 1；r8 存活并恢复新鲜数据。故障注入报告 `/home/agi/lxh-supermimic/trials/imu-pipe-backpressure-20261104-r1/report.json`。

## r8 修改

独立容器版本 `/home/agi/lxh-supermimic/releases/11500_zero_xy_20261104_r8`，保留 r7。改动集中在读取器与诊断元数据：

- 校准前不发送超过 35 ms 或缺少完整因果编码器的无效候选，原始输入仍进入有界 anchor 重放缓冲；校准不使用这些旧候选。
- 管道写满 EAGAIN 时仅停止传输当前快照，继续接收传感器。校准前保留原始锚点缓冲，校准后每条 IMU 已完成积分；不因 Python 暂停而堵住原始传播。其他写入错误保留报错，并增加 errno 文字。
- 移除“50 ms 未分发 C++ 回调就杀死读取器”的重复判断。此前静止完整采集已有 header 连续但回调暂停 206.8 ms 的证据；此判断不能区分传感器断采与调度暂停。继续按真实 header 检查重复/回退及超过 40 ms 原始间隔；下游发包 35 ms 新鲜度、worker 50 ms 状态检查与硬件目标租约不变。无消息时不产生新状态；初始 20 s 校准期限与校准后 500 ms 首包期限保留。
- 元数据明确原生路径没有 wall-clock callback 自退出，Python 后备路径原 50 ms 输入检查不变，不把诊断字段写成仍执行原生 50 ms 超时。

r7 的 stand/原地左右转世界水平反馈关闭设置保留。未更改积分公式、校准静止判据、策略权重、kp/kd、裁剪或硬件发布逻辑。

3. 27 项协议、积分数学、硬件状态桥与状态包测试通过。

两次状态源运行使用历史校准、`--observe-only --seconds 8`，只验证启动/传输/组包路径；未发布 ROS 状态或关节指令，没有真实静止校准、模型并行负载、运动精度或连续控制验收。故障注入也只调用读取子进程，给合成校准参数以检验缓冲和采样计数，不构成姿态或位置精度结果。未启动电机、模式切换或策略接管。
