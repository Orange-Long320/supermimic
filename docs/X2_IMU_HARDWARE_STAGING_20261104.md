## 估计与启动门槛

- 操作员必须确认物理静止；连续三秒的 IMU/编码器静止检查通过后才初始化重力方向、陀螺仪零偏和零速先验。20 秒内没有合格窗口则退出。没有用仿真吊挂夹具初始化真机。
- 航向以静止初始化时的任意本地零方向开始，之后由扣零偏后的原始陀螺仪积分。关闭在线加速度调平和 IMU 阈值零速更新。
- 真机 ROS 消息按点采样处理：陀螺仪梯形积分，世界系加速度线性插值积分；不伪造两个 1 ms 子帧或宣称设备做了区间平均。设备内部滤波仍未明确。
- 时间使用原始整数 header（积分时减去固定整数起点），不重打时间戳；重复/回退或间隔超过 40 ms、IMU 过期超过 35 ms、无 IMU 消息超过 50 ms、输出超过 50 ms 无新状态均退出（40/50 ms 为下文 r4 用户要求的调整）。历史记录表明 header 是接收侧语义，尚未证明等于硬件采样时刻。
- 编码器选择不晚于 IMU 的因果样本，最多滞后 25 ms，使用既有 schema2 原子包校验；高度来自关节 FK 和已声明的平地脚底几何。滑移、悬空和不平地仍有模型局限。
- runner 等待校准通过及新鲜状态心跳，之后才进入原有硬件发布/准备/接管流程。失败清理本次子进程。心跳不是运动精度、独立急停或电机验收证明。
- 原有人工试验的未验收控制参数（包含无目标范围裁剪、准备增益和接管方式）未因更换估计器而获得验证。启动入口保留原来的现场保护/急停人工确认，并加入静止校准确认。

## r5 修复准备：现有 Python 链路内减少阻塞

用户要求“修改好，不要过度设计”。12:57 trial `run-keyboard-20261104-125710` 已发布 180 帧，IMU 最大间隔 25.997 ms，最后一帧已通过校验并发出，随后报 `Coherent state output timeout`。

本阶段保持现有 Python/ROS/异步日志进程，不新增采集服务；40 ms IMU 间隔、50 ms 无消息等待及每包 35 ms 新鲜度校验保持原值。修改：

- 输出进度检查改用实际发布成功时的 monotonic 时间，50 ms 测量两次发布之间的间隔；原先用了传感器 header，混入已有接收延迟，可能在未达到 50 ms 发布间隔前退出。每个包的原始 header 校验以及下游 worker 的状态时效检查仍保留。
- 使用一个 `SingleThreadedExecutor`，节点只加入一次。实际 ROS Humble 的 `rclpy.spin_once(node)` 会在每次调用时 add/remove node，原先每条消息都重复这项工作。
- 心跳写文件交给既有有界异步日志进程；回调只入队。时间戳仍是生产时间，不能由写盘时间刷新。收尾等待队列后再次移除 ready 文件。
- 编码器标量检查使用 `math.isfinite`；历史保留 32 条，足以覆盖 25 ms 因果窗口；初始化后只在准备输出状态时重组编码器。校准后释放已保存原始日志的三秒窗口。
- 增加回调耗时统计及仅限 `--observe-only` 的完整处理诊断模式。诊断可载入过去的校准参数以测试计算负载，禁止用于真实状态发布；明确记录本次没有独立静止校准。诊断运行没有 ROS 状态/控制发布器，不代表当前校准或运动精度通过。
