# 实机只读影子部署：接触雅可比支撑融合（2026-11-02）

用户要求"用现在效果最好的算法，然后部署实机"。本轮只部署**状态估计器的只读影子**：进程不创建任何发布者、不接策略、不发电机命令，所有状态文件固定 `control_ready=false`、`motor_output_enabled=false`。电机与策略接管不在本轮授权范围内，未执行。

## 算法选择

离线实测中该配置最优：contact-Jacobian 足速 + 高度/竖直速度支撑门 + 新息自适应防滑，50 Hz 更新。同一场次对照中它优于 50 Hz 基线以外的所有变体，且**原生频率不适用于带接触更新的估计**（详见 `X2_NATIVE_IMU_RATE_20261102.md`）。

## 实现与部署路径

`scripts/deploy/shadow_contact_fusion.py`，在 `lxh` 容器内以 `/usr/bin/python3` 运行，依赖容器内 `python-cpu`（mujoco 3.16.0）。FK 使用既有 `lxh-fk-only` 模型与 profile（服务器已核验 FK 与完整模型零差异）。关节约 500 Hz、IMU 约 500 Hz，二者均在本轮只读采样中确认（leg median 2.00 ms、IMU 2.01 ms，error_code 全 0）。

## 四级结果：前三轮失败，第四轮可用但精度受限

| 轮次 | 结果 |
| --- | --- |
| r1（60 s） | 2930 tick 只有 10 次更新，位置发散到千米级 |
| r2（20 s 定标诊断） | 定位到水平残差 2.23 m/s²、`acc_world` z ≈ −19.36 |
| r3（30 s） | 定标实现错误（对加速度重复旋转一次），仍发散 |
| r4（30 s） | 1475 tick 全部接受，位置有界，静止漂移 0.380 m / 30 s |

### 根因一：姿态与加速度不共架，且重力符号相反

r2 记录显示 `|a_body|` 中位 9.806（比力含重力），但 `R(q)·a` 的静止均值是 `[-0.18, -2.22, -19.36]`：z 分量约为 −2g，说明符号相反；水平残差 2.23 m/s² 等效 13.1° 姿态偏差。实测腰部 pitch 中位 0.333 rad（约 19°），与仓库已记录的"吊挂姿态本身倾斜约 20°"一致。

处理：启动时用 3 秒静止窗估计把比力映射到 +z 的旋转（本轮得到约 29.6° 绕 y 的校正，残差 1.8e-15），并要求静止窗内 `|a|` 在 9–11 m/s²、`|gyro| < 0.05 rad/s`，否则拒绝启动。该校正是**单重力向量拟合**，绕竖直轴的偏航不受约束，且只在标定时的腰部姿态附近成立，不是完整外参标定。

### 根因二：脚高左右不对称，指向未验证的关节零位

r4 静止时模型坐标下左脚踝 0.4103 m、右脚 0.3391 m，相差 7.1 cm；支撑恒定为右脚、全程无切换。这一不对称与仓库已记录的 `left_knee_joint = −0.0659`（超出 URDF 与模型下限 0.0）指向同一问题：编码器零位/方向未验证。

代价是可量化的：静止 30 秒位置漂移 0.380 m（≈1.3 cm/s），速度残差约 9 mm/s。仿真同一算法在静止段只有 0.1–0.3 cm/s，差距来自实机运动学一致性，不是滤波器本身。累计 60 秒将达约 0.8 m，远超 anchor 可容忍量级。

## 时序与资源

r4：tick 49.2 Hz，FK 最大 2.9 ms，单 tick 最大 9.0 ms，IMU 年龄最大 20.5 ms，关节年龄最大 24.9 ms，无一次因年龄被拒。容器内 ARM64、单进程、无 GPU。

## 边界

- 影子估计，无真值；0.380 m 是"估计位置在机器人静止期间的变化"，不是已测定位误差。
- 单重力向量外参拟合，偏航不受约束，腰部姿态变化后需重标定。
- 接触点是踝体原点，不是足底接触点；无实测接触力。
- 未接策略、未发电机命令、未做控制权切换；策略接管仍受既有四项阻塞约束（准备接管动力学、关节零位/命令合同、骨盆状态链验收、发布者交接）。

### 关键限制：被吸收的"偏置"大部分不是传感器偏置

水平残差 2.223 m/s² 与 13.1° 的姿态错配给出 `9.81·sin(13.1°) = 2.23 m/s²` 完全吻合。也就是说卡尔曼吸收的主要是**姿态/安装错配**，而不是传感器零偏；它在本轮成立，是因为机器人全程静止、姿态不变。一旦转向，这个等效偏置会随姿态旋转，估计会重新出现同量级泄漏。

因此本方案当前只被验证于**静止站立**：站立精度优于此前所有方案，且不依赖未验证的关节零位。行走与转向下的表现未测，也不应由本轮数据推断。

证据：`/home/agi/lxh-supermimic/shadow-contact-20261102-r1/{integ-200-neg,integ-200-bias,kalman-zupt-r1,kalman-zupt-r2}`。

### 更正为传感器速率（500 Hz）

用户更正目标频率为 500 Hz。定时器路径实测只能到 172 Hz，因此改为**在 IMU 回调内直接积分**，不再经过固定周期循环。

| 运行 | 积分速率 | 全程最大偏离 | 末端偏离 | 相邻积分间隔 p99 / 最大 |
| --- | ---: | ---: | ---: | --- |
| 定时器 200 Hz（r2） | 172.2 Hz | 0.0001 m | 0.00006 m | — |
| 回调，QoS 深度 1（500-r2） | 467.7 Hz | 0.00008 m | 0.000014 m | 5.1 / 8.5 ms |
| **回调，QoS 深度 20（500-r3）** | **500.2 Hz** | **0.00014 m** | **0.000095 m** | 5.1 / 15.7 ms |

结论：把订阅队列从 1 加深到 20 后，积分速率从 467.7 Hz 提到 **500.2 Hz**，与只读采样测到的传感器速率一致；IMU 年龄最大 1.0 ms（定时器路径是 31 ms），因为样本在回调中立即处理而不再等待下一个 tick。静止 30 秒全程偏离 0.14 mm。

仍为静止站立结论，行走与转向未测；被吸收的偏置依旧是姿态错配，转向后失效。

## 姿态外参标定：13° 错配在 x 轴，不在 y 轴

在世界系拟合把实测重力方向映射到 +z 的最短旋转（静止 3 秒窗），得到

```
x = +13.11°, y = −1.04°, z = −0.12°   残差 0.0000 m/s²
```

拟合后初始偏置为 `[0, 0]`，收敛后 `|bias| = 0.0004 m/s²`。也就是说此前被卡尔曼吸收的 2.22 m/s² **全部**来自这个姿态错配，不是传感器零偏。

对照：只加 y 轴 −1.04° 校正（用户指定的 y 轴参数）时，偏置仍是 `|bias| = 2.2234 m/s²`，初始偏置 `[0.0044, 2.224]`。**说明有效轴是 x，不是 y**；y 轴只有约 1°，单独校正后 13° 的错配原样保留。

三次运行的真实积分速率（按帧时间戳统计）都是 500 Hz：

| 运行 | 积分速率 | 全程最大偏离 | 末端偏离 | 收敛后 \|bias\| |
| --- | ---: | ---: | ---: | ---: |
| 无外参校正（500-r3） | 500.2 Hz | 0.14 mm | 0.095 mm | 2.2299 |
| **自动拟合（含 x 13.11°）** | 500.3 Hz | 0.08 mm | 0.053 mm | **0.0004** |
| 仅 y 轴 −1.04° | 500.1 Hz | 0.09 mm | 0.006 mm | 2.2234 |

静止位置漂移在三者中都已很小（零速更新主导），**区别体现在偏置状态**：外参正确时偏置收敛到零，说明物理模型自洽；外参错误时偏置停在 2.22，说明滤波器在持续抵消一个真实误差。后者在姿态改变时（转向）会失效，因为世界系偏置不会随姿态旋转。

参数入口：`--auto-mount`（自动拟合）或 `--fix-deg-x/--fix-deg-y/--fix-deg-z`（手调世界系角度）。`achieved_rate_hz` 字段在早期版本包含标定窗口，按帧统计为准。

## 更正：四元数顺序错误，13.11° 外参是伪结果

在给状态包补高度时发现 FK 输出 `pelvis height = −0.52 m`（负值即模型倒置）。逐层核对后确认根因：

**设备发布的是 w,x,y,z，scipy 需要 x,y,z,w。**此前所有估计脚本都把 wxyz 直接传给 `scipy.spatial.transform.Rotation.from_quat`。同一帧数据两种顺序的 FK 结果：

| 四元数处理 | 双脚踝高 | 骨盆高 |
| --- | --- | --- |
| wxyz 当 xyzw（错误） | +0.5659 / +0.4981 | −0.4981 |
| 正确 xyzw | −0.5712 / −0.5707 | **+0.5712** |

此前那套流程能"工作"，是因为错误的旋转是一个固定变换，被世界系偏置状态和一次单向量重力拟合同时吸收了：拟合只约束一个轴，所以 13.11° 这个数字本身是在错误坐标系里量出来的。

修正后重测：外参拟合结果 **x=0.00°、y=0.00°、z=0.00°，残差 0.0000 m/s²**。设备 IMU 姿态本来就是正确的，**不存在 13° 安装错配**。同时重力符号也要改回 `+R(q)a`——原先的负号是在补偿错误四元数。

修正后状态包实测（`producer-r7`）：

| 指标 | 数值 |
| --- | --- |
| 发布速率 | 45.9 Hz |
| 无效包 | 0 / 921 |
| 包年龄最大 | 6.3 ms |
| 因五路时间跨度跳过 | 64 |
| 骨盆高度（FK） | **0.6208 m** |
| 独立 LIO 参考 | 0.619–0.637 m |
| 水平漂移最大 | 8.4e-5 m |

高度 0.6208 m 与独立雷达记录吻合，是这次修正正确的旁证。

**范围说明**：修正目前只落在 `publish_pelvis_packet.py`。`shadow_imu_kalman.py`、`shadow_contact_fusion.py`、`shadow_imu_integration.py` 仍带同一缺陷；它们的水平漂移结论自洽（偏置状态吸收了固定旋转），但任何涉及姿态输出或 FK 的量都不可用。
