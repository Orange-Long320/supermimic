## “部署后自动到准备姿态”的接口边界

模型文件已在机器人上，不等于电机闭环已启动。11500 导出只计算策略动作，没有独立的慢速准备状态机。现有 SDK 独立部署示例 `motion_control_node.cc` 也明确区分 `JointDefault()` 的实测姿态插值与 `RlDefault()` 策略推理；不能把模型加载当成准备动作。

正确的独立执行顺序是：原生 MC 关闭 → 从新鲜实测姿态缓慢准备 → 到位/速度/身体姿态检查 → 连续真实观测历史 → 连续交接到 11500。准备由程序发送电机命令完成，不要求用户手动掰关节。未通过准备和接管时，不直接从自然下垂姿态发布 11500 输出。

官方 RL 部署仿真教程的手柄映射为 △ 位控、□ RL、○ 阻尼、× 零力矩，建议先位控再进入 RL。机载示例 `JointDefault()` 捕获当前关节位置，在 1.5 秒内线性插值至配置默认姿态；切换到 `RlDefault()` 时先预热推理历史再进入策略。示例未证明 11500 的接管通过，且官方说明这两套示例只在仿真中验证，其增益是仿真参数。官方独立 RL 示例和原生 MC 模块是不同路径，不应同时驱动机器人。教程：https://x2-aimdk.agibot.com/zh-cn/dev/rl_contents.html ；范围说明：https://x2-aimdk.agibot.com/en/latest/sim_rl/index.html 。

2026-11-01 官方准备动作对照：SDK 位控默认目标与本项目 11500 准备目标不同，例如双肘分别相差约 1.156 rad、双膝约 0.478 rad，因此不能假定官方动作结束即已进入 11500 的准备姿态。沿用旧实测快照的接地对齐反事实、仿真中临时解除四个初始超限，并令吊挂预载为零，按 20 ms 采样近似 SDK 的 1.5 秒线性插值和 SDK 仿真增益；项目自己的接管门限仍保留，未运行原厂控制器。仿真约 0.48 秒触发高度或倾角门限，未进入接管。记录 `preparation-official-contact-aligned-20261101-r2`；结果不能证明实机必然失稳，也不能算通过。用同一旧接触对齐快照和模型的慢速轨迹对照此前同样在 0.48 秒失败。

对较新只读姿态，用官方仿真场景的足部视觉网格顶点投影与接触球投影比较：重心距各自凸包约 69.3 mm 和 74.5 mm（在凸包外），最低网格顶点相对最低球面分别低约 0.9 mm 和 0.6 mm。两者均包含未接触地面的部分；它们不是实际支撑多边形，模型网格与实机文件的逐文件一致性尚未验证，骨盆姿态和地面估计也未定标。记录 `mesh-projection-latest-20261101-r1.json`。

追加核对：服务器仿真脚的左右 STL 与机器人 PC2 安装的官方 RL 仿真示例、`mc-rl` 示例 URDF 所带的左右 STL 各自 SHA256 一致（左 `47a3b755fc7c3bd4c61f7b26fd75bff2046601d64491709f6f5f62334ee310f8`，右 `8f5d26addecdbd6fff8bef111a9f50d1c220421096a97e9f217fa7d00c8582e3`）。这确认示例资产一致，不能确认实际零位或动力学已标定。把胯部 IMU 用于静态方向反事实后，网格投影凸包外约 38.0 mm，碰撞球凸包外约 42.4 mm，仍不代表实机支撑或失稳；记录 `mesh-projection-pelvis-counterfactual-20261101-r1.json`。

## 支撑假设实验的结果与适用范围

以下都不是当前实机条件的验收：

- 放宽 **仿真** 接管倾角到 0.26 rad 的反事实对照中，“先接管再卸载”虽末段站稳，交接和早期控制出现最高约 666 N 自碰撞；全程保持承重吊挂也持续摆动。不能仅凭没有提前终止或末段站稳判成功。
- 5 秒同步交接/卸载，末段 30 秒未倒，但交接阶段倾角最高约 32.6°、角速度 5.21 rad/s、力矩饱和、自碰撞最高约 773 N，仍失败。主要碰撞为 pelvis 与 hip_roll_link。
- 1 秒交接配 1/3/5 秒卸载，均有交接自碰撞（约 619/139/138 N）及力矩饱和；没有可发布到实机的通过项。
- 单独把准备增益改为策略增益，没有消除交接后的碰撞（最高约 615 N）；不能将增益差异直接写成已解决的根因。
- 基于模型 COM/吊点关系的腰部姿态候选，在 16.12 秒触发倾角/高度门限，未接管。它同样依赖旧吊挂假设，不继续用作当前实机方案。
