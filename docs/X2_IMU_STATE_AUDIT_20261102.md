# X2 IMU 状态估计审计（2026-11-02）

范围仅为源码审计与服务器仿真轨迹离线重放；没有机器人操作或实机部署。回档基线 `ded494a6a427cf64329f68adba45985b77df919d`。本次修改和结果均不构成可部署状态估计器。

## 发现

1. `publish_pelvis_packet.py` 的水平位置是 IMU 积分结果，姿态、角速度、重力也直接取 IMU；FK 时把 IMU 姿态作为骨盆姿态，没有应用腰部运动学和安装位姿。现有 `UrdfPelvisMount` 可计算腰部相对位姿、线速度和角速度，但生产者没有使用它。正确速度转换需要减去骨盆旋转造成的杆臂速度和腰部运动造成的相对速度；本次增加独立转换函数并做有限差分关联测试，尚未接入生产者。
2. 原积分使用回调单调时钟并截断间隔，不是 IMU 采样时钟。已改用原生 header，相邻时间非递增或间隔超过 30 ms 报错，首帧只建立时间基准。姿态和比力取自同一个 IMU 消息，但仅凭此不能证明设备内部传感器同步。生产者使用最新关节快照，把状态时间写成五路最大值，不能使 IMU 和关节真正同步；现有关节跨度检查还没有涵盖最早 IMU。该问题未修复，不应把该包视为同步骨盆状态。
3. 原初始化循环每次 spin 后重复读取最新 IMU，不验证静止或采样连续性。已改为只在 IMU 回调收集一次，检查窗口时长、时间连续性及每样本角速度/加速度幅值门限，不满足则拒绝初始化。惯性幅值门限只能排除部分运动，不能证明绝对静止或排除匀速运动；也不能区分倾角、传感器零偏及线加速度。世界系二维常量偏置不是随姿态旋转的传感器体系零偏模型。自动单重力向量校正无法标定偏航和完整外参。
4. 现有 ZUPT 是 IMU 自身静止时的零速测量，并非行走支撑足约束；持续走动缺乏有效速度/位置观测，偏置不可持续校正。静止门限本身也不足以保证 ZUPT 无误判。
5. 旧记录器没有存关节 header，故不能重建腰关节与 IMU 的采样同步。新记录器保存关节 header；旧数据不能补造时间戳。
