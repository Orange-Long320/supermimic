# 32步来源与世界模型适配审计

2026-10-29。用户要求核实32步的设计依据，并区分世界模型训练不足与新增速度控制的配置适用性。本次只做隔离诊断，没有切换正式策略、修改运行中的训练或采用候选世界模型。

## 上游依据

- [原论文](https://arxiv.org/pdf/2610.28480) §3.2–3.3明确区分模型训练窗口k=8与策略想象H=32，二者不要求相等。32步覆盖0.64秒，末端critic估计后续回报。作者解释，自回归拟合使模型能学习纠正自身预测误差；这是其模型的论述，不是本项目已验证性质。
- §4.3、Fig.4在LAFAN1比较H=8/16/32/64/128：带critic的32步最快达到0.82目标，8步两种变体均未达到目标。因此把H降到8可能损失长期信用分配，不能视为通用修复。
- 原论文Appendix B/G还训练速度接口：共享动力学和decoder，速度奖励只更新速度encoder，使用混合接口仿真数据。没有报告针对X2或本项目五段动作的H最优值，也没有单独的速度接口H扫描。
- [参考实现README](https://github.com/CuboiLeo/SuperMimic-Reproduced/blob/d9be385b3eeb13a638fb33fb200d3bfd9be9839f/README.md)注明默认超参遵循Table A.5，且其固定版本未实现速度接口及H×critic消融。应区分论文实验与参考复现实现。

世界模型继承了LAFAN70000底座，并非从零只训练1320步。当前一小时适配末期计数为1320/496次联合更新；不能据此宣称充分收敛，也不能忽略预训练及此前阶段。论文速度任务训练100000次迭代，数据与初始化均不同，不能按小时直接类比。

当前参考库实际为五段视频派生动作，共947帧、约18.94秒；不等同于论文的LAFAN1+BONES-SEED步行/跑步库。仿真转移可持续采集，不局限于这18.94秒。代码已把速度环境的真实带噪执行动作纳入世界模型回放，未发现“模型完全没有训练速度数据”。速度目标不作为动力学输入本身符合共享物理模型设计。

速度奖励也不是论文的逐项原样复现：本地平滑惩罚为-0.1（论文速度任务为-0.3），本地额外约束根部直立、竖直速度、高度和停止姿态。不能只核对H就宣称整个速度协议等价；这些偏离的因果贡献本轮未单独消融。

### 统一精度后的主要结果

以下均为**独立轨迹上32步末端的速度预测RMSE**，不是实际指令跟踪误差。

| 同一32步窗口数据上的干预 | vx m/s | vy m/s | yaw rad/s |
|---|---:|---:|---:|
| 原1000步世界模型 | 0.1562 | 0.1438 | 0.2751 |
| 8步状态损失，512次更新，batch512 | 0.1908 | 0.1439 | 0.2779 |
| 32步状态损失，128次更新，batch512 | 0.1063 | 0.0830 | 0.2739 |

两个分支使用相同录制窗口、初始权重和TF32；模型预测步数预算均为2,097,152。Adam更新次数不同，这是固定展开步数预算下的比较，不是所有优化变量都相同的严格单因素消融。两组原模型baseline所有标量最大数值差为3.08e-5；未声称逐bit复现。

32步模型拟合能减少前向与侧向长期偏移，说明该范围并非天然不可学习；偏航没有得到持续改善，仍不能作为已修复世界模型。64次更新时表现更好而128次回退，也不支持仅凭单个中途最优点宣布成功。

另一个恢复batch2048、保持8步损失并额外训练512次的TF32分支，32步速度预测从`[0.1453,0.1361,0.2778]`变为`[0.1796,0.1222,0.3321]`。训练集8步总体NSE从0.02835降至0.01064，但长期前向/偏航未改善。仅增加固定小语料上的短窗口拟合，并不能保证长期任务速度或独立轨迹表现。

原模型在跟踪轨迹上的32步误差约`[0.1682,0.1366,0.2611]`，与速度轨迹同量级；问题不是只发生于新增速度接口。1320步模型在相同早期策略轨迹上也没有一致优于1000步模型，详见原始指标。

### 保留的失败对照与限制

早期`large-batch`及`window32-control`在复用离线窗口时没有调用`make_env`中的TF32配置，精度条件不一致；其数值不用于最终匹配结论，已补齐后重跑为`large-batch-tf32`与`window32-tf32`。早期8步batch256的两个分支亦未得到可靠改善，保留为诊断，不替代正式batch配置。旧window32分支的说明字符串误写8步，实际`fit_window`、命令及循环均为32；最终版已修正说明。

所有指标及来源见[诊断JSON](KEYBOARD_WM_FIT_AUDIT_20261029.json)。窗口/权重约几十至几百MB，只在服务器保留。模型拟合峰值PyTorch保留显存实测低于1.5GiB；不把此值作为完整策略训练显存。

## 结论及后续修复边界

1. 不能把“k=8、H=32不相等”当成根因；原论文有意采用该组合，并有消融依据。
2. 已证实本项目世界模型在当前混合步态分布上的长期速度预测不足，且模型拟合配比显著降低。证据更指向世界模型适配与长期任务准确性的缺口，而不是速度接口天然不适合32步。
3. 尚未证明“只差训练时长”或“2批是唯一原因”。额外短窗口拟合不能稳定消除误差；较长模型损失仅改善部分分量。新数据覆盖、误差权重/模型表示、在线策略分布变化及优化梯度可靠性的贡献，仍需后续对照区分。
4. 此前缩短策略H只能算限制误差影响的候选措施，物理PPO能改善控制也不等于修复世界模型；两者均不能关闭本问题。
5. 后续应先恢复模型拟合强度作为对照，使用持续更新的混合接口数据，分别监测1/8/16/32步的root速度与偏航；验证物理回报方向与模型梯度一致后，再以相同预算比较策略H=8/16/32。长训采用哪个H须由这些结果决定，不能凭短窗口NSE或想象奖励选定。

本轮没有执行上述完整在线策略消融，因此没有“32步已修复”或“8步已经足够”的结论。
