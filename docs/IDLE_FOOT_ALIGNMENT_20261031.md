# 实测落脚对齐的 Idle 终点与收步过渡

用户要求将 Idle 终点按实际落脚位置对齐，构造可达收步过渡，并使用相同日程做长站立对照，不使用 PPO。起点 `400cdad`，开始时工作区干净。冻结原 11500 策略与原始参考，不改碰撞模型，不启动策略训练。

拟实现两阶段规划：先沿用原制动；当未来窗口已静态，且实测脚部几何与速度满足有界的落脚准备条件，再用实测脚位构造固定终点。腿部和根部 IK 保持双脚终点位置/平放方向，保持原上肢目标，约束 COM 几何范围、机械限位、速度及穿地；过渡包含初始几何修正、重心转移、一次收脚、回到双脚保持。支撑标签仅是几何规划代理，不是已测接触力；运动学和 LIPM 检查不等于真实动力学通过。

新规划参考需要一次世界坐标配准，丢弃已有的积分位置偏差；配准只改变参考坐标，不写回机器人状态。已发布的关节/速度未来窗口保持，配准事件及 anchor 的变化必须记录，不能把它隐藏成完全连续的旧世界轨迹。终点一旦确定后保持固定，不能逐帧追随机器人来掩盖漂移。规划使用独立 worker，主控制继续发原静态参考；过期上下文拒绝重用。

先在服务器 CPU 对真实记录构造并审计参考，核验时间与可达性；再用隔离官方仿真、CPU 推理/软件渲染，比较原上下文规划器与落脚对齐版本。沿用三次 Walk/Idle 日程和 90 秒墙钟预算，比较松键距离、运动速度、共同 10/40 秒窗口与新模式实际完成时刻。未通过的步骤保留失败记录，不称为修复。
