# X2 Walk / Idle 上下文规划原型

已完成首轮独立原型和官方仿真对照。原型可连续执行 Walk→Idle→Walk，但停止与站立指标没有稳定优于原调度，保持实验候选，不替换默认入口。没有训练、没有 PPO。结果见下文；不能把无终止称为物理验收。

后续[根因排查与长窗复测](IDLE_DRIFT_ROOT_CAUSE_20261031.md)发现首轮新旧排序未稳定复现，并定位到终点与实际落脚不一致、缺少直接实测平移速度反馈等共有缺口。速度阻尼仅短窗改善，40 秒长窗未优于对照，未采用为默认修复。下文首轮数值保持原样，不能将其解释为新规划器造成稳定回归。

用户于 2026-10-31 确认尝试 X2 的简化上下文规划器。本轮先做 Walk→Idle→Walk，复用原始五技能 11500 跟踪器、原始动作与收步参考，不启动新的命令相位策略训练。修改前基线 `2689648`，工作区干净。

实现计划：在保持已发布未来窗口不变的前提下，依据窗口末端、实测关节位置/速度及脚部几何，检索原参考中的过渡入口并选择衔接时长；生成连续关节位置/速度和根部速度参考，交给现有 SuperMimic 跟踪器。第一版是检索与约束插值原型，不是 NVIDIA 模型复现或已验证的动力学规划器。不引入 PPO；如后续需要学习，仍使用世界模型与可微想象。

检查时四张 RTX 3090 均被其他用户任务占用。计划先在服务器执行 CPU 算法与参考检查，并检查官方仿真软件渲染可用性。独立原生 MuJoCo 控制链此前未对齐官方链路，不能将其失败或接触力用于评价本次官方效果。当前尚无新实现或仿真结果。

## 原型与启动前检查

源码 `623d4a7` 加入独立 `ContextIdlePlanner` 与显式 `--planner context-idle`，默认仍为原调度。候选来自原 walk / walk_stop 的三个入口和两种衔接时长；依据已发布窗口末端、最新实测关节位置/速度和 FK 脚踝几何排序。使用短段 Hermite 修正，再接回原记录。排名时的实测误差外推是启发式，不是动力学状态预测；脚踝几何不代表接触力。保留 10 帧已发布窗口，不能立即重写未来。

服务器 `logs/idle_context_20261031_r1/` 保留隔离源码、单元测试和参考检查。初版参考检查发现继承的 sustained 循环拼接会令左腕 roll 超出机械上限约 0.00660 rad；固定 99→152 帧的 10/15/20 帧衔接均未通过新机械筛选。诊断发现结束帧提前一帧可通过。新原型初始化时在原结束帧附近 ±2 帧内筛选合法接缝，实选 walk 99→151，且循环和启停均检查机械限位及标称/差分速度。不修改原始 NPZ 或默认调度器。对照两组因此比较整个调度器，不能将所有差异仅归因于停止入口。

`reference-audit` 首版失败、`reference-audit-r2/r3` 拦截记录均保留；r3 还错误检查了本轮不支持的 jog，已将原型循环准备限定为 walk。`reference-audit-r4` 的 3.6/4.0/4.4 秒前进、停止和再次起步三条理想反馈序列通过：未来重叠误差 0、最终静态参考误差 0、最大机械超限 4.02e-6 rad（容差 1e-4）、最大差分速度比 0.2473；最大单次 goal 调用约 4.14 ms，仅代表服务器 CPU 参考检查，不是实时性或物理验收。新增及相关单元测试共 9 项，最终结果见 `tests-final.log`。

软件 OpenGL 检查已返回 Mesa llvmpipe / LLVM 15.0.7，官方仿真拟采用 CPU 推理与软件渲染（CUDA_VISIBLE_DEVICES 为空），不使用其他用户 GPU。复制自已有官方仿真配置的独立 fixture 使用 ROS domain 201、UDP 19279/19280、HTTP 51991；依赖和二进制只读复用，配置与工作目录独立，重新按原 walk_stop 末帧初始化。冻结策略 SHA256 `4424f231fc1896da098b2fca366e8522df6791596638b2b9257ba682520bbe4c`，数据 manifest SHA256 `592501503dcdf668262417b11334f56a20e8f360cf00ad82849821fae0b9b45c`，所有 NPZ 在运行前逐个核验。入口 `run_idle_context_comparison.py` 顺序运行 baseline / context-idle，相同三次前进与松键，单组 55 秒墙钟上限；只清理自身创建的进程组。官方结果此时待执行，未启动训练。

这是每个规划器各一条顺序轨迹，不是三个独立随机试验；日程相同不代表两者真实关节相位相同，循环接缝也有差异。原型未明显丢失本次前进速度，但第二次停步距离、后两次脚尖偏差和站立漂移变差，没有显示一致收益。两组均有毫米级脚部几何穿地，原型松键后 5 秒内最低约 -6.09 mm；50 Hz 事后几何审计不是接触力，也不是物理子步峰值。

结论：检索和短段插值链路已可跑，仍不足以作为停止问题的修复。现有候选仅覆盖原 walk_stop 的不同入口，没有接触受力或动量约束，不应仅按姿态/速度匹配分数判断可执行性。后续应先增强过渡候选和支撑/动力学判据，再比较多初始化、更多松键时相、长站立与其他技能。本轮不延长训练、不扩大为默认键盘控制。

原始轨迹与独立审计分别保存在 `baseline/policy/`、`context-idle/policy/` 及各自 `audit.json`，等长窗口和移动回归检查为 `summary-v2.json`（入口 `compare_idle_planner.py`）。一次额外的高质量 CPU 回放渲染因耗时而主动中断，日志及部分文件保留，不作为完整演示；不影响已经完成的仿真和审计。所有本任务仿真与该渲染进程均已退出。
